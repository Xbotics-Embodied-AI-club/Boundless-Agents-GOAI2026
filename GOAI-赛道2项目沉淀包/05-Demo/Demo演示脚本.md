# Demo 演示脚本（3—5 分钟）

## 演示目标

只证明一件事：用户不是“问完一个问题”就结束，而是在一个真实教育任务中完成学习、作答、诊断、补学和再验证。

## 0:00—0:30 开场

“这是‘身知回响’，面向具身智能入门者和转岗产品经理。我们发现，用户看完很多资料后，依然回答不了一个真实问题：仓储 AMR 为什么不能只用相机？所以我们没有再做一个聊天框，而是把 Agent 放进一条可验证的学习任务。”

## 0:30—1:00 能力地图选点

操作：首页展示能力地图，进入“感知与传感器—激光雷达与测距”。

讲解：“这张图不是课程目录，而是岗位能力地图。每个节点必须由解释、判断和案例证据共同点亮。目前我们重点完成并验证了传感器选择这一条分支。”

## 1:00—1:45 学习伙伴 Agent

操作：进入学习伙伴，提问“为什么仓库机器人不能只用相机？”

讲解：“学习伙伴 Agent 会读取当前节点、已完成步骤和知识依据，再回答问题。回答后它不会直接替用户完成任务，而是继续追问：在弱光、粉尘或反光环境中，相机会发生什么？激光雷达又能补足什么？它的目标是推动用户形成解释。”

## 1:45—2:35 真实挑战与费曼复述

操作：进入仓储 AMR 挑战，选择传感器组合，并用自己的话解释。

示例回答：“相机适合识别语义目标，但容易受光照影响；激光雷达能稳定测距和构建几何信息，但也存在玻璃、反光和成本问题，所以需要根据速度、通道宽度和环境变化组合传感器。”

讲解：“这里要求用户做取舍并给出边界，不是选择一道标准答案。系统记录的是任务证据。”

## 2:35—3:20 学习评估 Agent 与规则门槛

操作：提交解释，展示五维诊断和下一步建议。

讲解：“学习评估 Agent 从解释、判断、案例证据、迁移和风险意识五个维度定位缺口。比如用户只说‘激光雷达更准’，系统会追问准确性在什么条件下成立。需要强调的是，Agent 只负责诊断和建议；节点是否掌握由确定性规则根据证据判定，模型不能自己解锁。”

## 3:20—4:05 迁移任务

操作：切换到夜间仓库/反光材质等变化场景，再做一次判断。

讲解：“如果用户只能复述原答案，但无法迁移到新场景，系统不会把这项能力判定为稳定掌握。完成迁移后，闭环才真正结束。”

## 4:05—4:40 个人项目学习 Agent（可选）

操作：展示项目文件导入入口或生成后的项目学习计划。

讲解：“第二条能力是把用户自己的 PDF、DOCX、Markdown 或 TXT 项目材料转为项目知识图谱、学习目标、关键问题和证据账本。文件仅临时处理，分析结束或失败后删除；模型不可用时会返回明确标注的降级计划。”

## 4:40—5:00 收尾

“因此，身知回响中的 Agent 不是一个独立聊天功能，而是嵌入‘选点—学习—行动—解释—诊断—补学—再验证’的流程。当前已有可运行 Web Demo、小程序代码和自动化测试，下一步会扩展更多真实具身智能任务，并增加带教者诊断视图。”

## 演示失败时的备用方案

- 云端模型失败：切换到本地知识 Agent，说明这是产品设计中的可控降级，不掩饰服务不可用。
- 小程序体验版权限失败：使用本地 Web Demo 的 `/agent` 页面，演示相同的上下文辅导逻辑。
- 文件选择失败：展示已生成的项目计划结果和数据处理流程，不在现场反复授权。
- 网络不稳定：优先演示离线能力地图、微课、挑战和规则判定；云端问答改用录屏。
